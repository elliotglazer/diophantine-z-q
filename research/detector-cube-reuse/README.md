# Reuse a stored cubic: 380 variables, or 383 with smaller coefficients

The detector's contact-polynomial circuit already provides `(98t-1)^3` as
an affine expression. Reusing it removes one weight coordinate in each of
the three detectors. The default construction above #12 has **380 total
variables and 682-digit coefficients**. Combining this with the separately
proved order-47 route gives **383 variables and 646-digit coefficients**.

Both are complete compiled counts, including the input. The new local change
is an exact projection equivalence; the arithmetic interpretation remains
conditional on the inherited inputs. It does not make a new current
manuscript edition or assert general optimality.

Read [PROOF.md](PROOF.md), [APPLICATION_CONTRACT.json](APPLICATION_CONTRACT.json)
and the cumulative [HANDOFF.md](HANDOFF.md). The optional precision argument
is retained verbatim with an exact origin record under `references/`.

```sh
python3 -B research/detector-cube-reuse/reproduce.py --output build/cube380
python3 -B research/detector-cube-reuse/reproduce.py --order 47 --output build/cube383-small
```

Use absent or empty output directories. Python 3 and Node, with no
third-party packages or network, suffice. The replay checks the actual
affine cubic in all three detectors, all changed and outside rows, guards,
four corrupted-source controls, every source gate/compiler operation, the
unused-slot omission, four conic transports, every scaled row and every
quartic coefficient. Source bindings are checked before and after the run.
These finite checks do not establish the global arithmetic theorem.

The packet supplies a deterministic generator and expected artifact hashes.
Full decimal expansions are generated by replay and uploaded by CI; they
are not committed in this directory. The previous selected 383 packet and
all its original review bindings remain unchanged.
