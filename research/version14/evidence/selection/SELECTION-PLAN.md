# Version 14 handoff selection plan

This author proposal changes no repository, creates no archive and issues no approval. `INCLUSION-PROPOSAL.json` gives an exact observed local source path, proposed repository-relative destination, byte count, SHA256 and status for every proposed file. Pending items have no invented source or hash. The final inclusion reviewer must resolve active records and bind the selected committed bytes.

The 520-file frozen 299/314 package is selected exactly from its manifest. Three public coefficient copies use the R4 installer's exact destinations. The remaining dated optimization, under-400 and under-300 research is catalogued; 464 original files were already present byte-for-byte in the package and are mapped there instead of copied again. History includes rejected candidates and unsuccessful routes. The proposed scope is deliberately cumulative rather than only the successful final branch.

`coverage-selection.proposed.json` has the R4-required three-key schema. It lists only existing proposed paths. It is a draft path classification, not evidence that coverage is complete. Final whole-proof coverage, final reconciliation, the fresh assembled-proof decision, current registry approval pins, final PDF/build/visual records and actual release/restore receipts require completion or exact final binding. The proposal's pending list names intended destinations; those names are proposals, not claims that the files exist.

The R4 builder's final selection is a flat object `{repository_relative_path: sha256}`. This proposal intentionally uses a different schema so it cannot accidentally serve as that final input. The builder also checks the exact protocol hashes, current register's manuscript and approval pins, every package member, public table equality and inventory install membership. Those checks remain mandatory. Merely selecting a review file does not make its verdict applicable to a later source hash.

`INTERPRETER-SOURCE-MAP.json` retains all 34 original supplier pins. It identifies exact existing repository matches and proposed copies, including the first 14 code/machine inputs. The licensed PDF is excluded. The map changes no original report or source-pin bytes. Existing matches are reused rather than replaced by renamed copies.

The exclusion list is explicit. New full papers, extracted full texts and paper screenshots are omitted even where local audit manifests mention them. Credentials, conversations, raw account logs, compiled caches, nested candidate ZIPs and unrelated files are outside the proposal. The retained `.log` files are research/reproduction or test outputs from the selected work directories. The retained machine and polynomial JSON files are mathematical artifacts. Final independent privacy review still needs to assess the exact selection, because filename and credential-pattern checks alone cannot establish absence of all sensitive content.

The new history layer is substantial. Do not trim a candidate or review merely to reduce size. Exact duplicates may be mapped to one selected existing file, with the mapping retained. Preserve runnable package layout and original source manifests; a historical absolute path inside an audit record is provenance, not permission to silently rewrite that record. Reproduction of arbitrary research experiments is distinct from the packaged finite replay.

Suggested final sequence: complete the actual pending source/deployment records; review the inclusion proposal and exclusions; install selected exact evidence; bind the final Git commit; generate the two final selection files; run the R4 cumulative builder and fresh restore/replay; add actual receipts and final immutable repository readbacks. No optimization or new mathematical search is part of this plan.
