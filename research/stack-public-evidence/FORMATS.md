# File formats

All text is ASCII except JSON string values, which are UTF-8. A `.gz` file is
a gzip stream holding the original file's bytes exactly. `INDEX.json` gives
two SHA-256 values for every file: one for the stored (compressed) bytes and
one for the decompressed bytes. The decompressed hash is the one the packets
publish.

## Decimal table: `quartic-<n>-balanced-decimal.txt`

The table has three header lines, then one line per monomial:

```
# Fully explicit integer quartic after an invertible diagonal change.
# Variables: <n>; input: x0; degree: 4; monomials: <m>.
# Format: integer coefficient, TAB, monomial; sum all data rows.
<integer>\t<monomial>
```

The polynomial is the sum of all data lines. A monomial is `1` or a product
of factors joined by `*`. Each factor is `xi` or `xi^e` with `e` in 2..4,
and the indices strictly increase. No monomial is repeated, and no
coefficient is zero.

## Plain-text rows: `rows-<n>.txt.gz`

This format is defined here and generated by `tools/derive.py` from
`balanced/integer-ir.json`. The table equals
`sum over rows k of (sum of the terms of row k)^2`, exactly over the integers.

```
# ... comment lines start with '#'
V\t<k>\t<irCoordinateId>\t<name>     one line per variable, k = 0..n-1 in order
R\t<k>\t<irResidualId>\t<name>       starts row k (k = 0..r-1 in order)
<integer>\t<monomial>                one line per term of the current row
```

- The variable `xk` of the table is the IR coordinate with the k-th smallest
  id. The `V` lines list that correspondence. `x0` is the input.
- Monomials use the table's syntax and have degree at most 2: `1`, `xi`,
  `xi*xj` with `i<j`, or `xi^2`.
- Every row is integral and primitive: the gcd of its coefficients is 1.
- To parse a file: skip `#` lines, split each line on TAB, and start a new
  row at each `R`.

## Quadratic IR JSON

There are two schemas. One holds the balanced rows,
`diagonally-scaled-integer-quadratic-ir-v2`. The other is
`brox-independent-quadratic-ir-v1` and is used for the raw, compiled,
pre-transport and pre-diagonal IRs.

- `coordinates`: a list of `{id, name, kind, protected, block, sourceLines}`.
  Ids are non-negative integers and need not be contiguous. Id 0, named
  `input`, is the input.
- `residuals`: a list of `{id, name, terms, ...}`. Each term is
  `{monomial, coefficient, sPower}`:
  - `monomial` is a list of coordinate ids; a repeated id is a power;
  - `coefficient` is a rational string such as `"-3/4"`;
  - the term's value is `coefficient * S^sPower * product of the coordinates`.
- `fixedParameter`, called `sourceFixedParameter` in the balanced IR, is
  `{"name":"S","value":"3^E","coordinate":false}`. `S` is a fixed integer,
  not a variable. In the balanced IR every `sPower` is 0.
- Raw IRs also contain:
  - `values`: named affine expressions in the same term format;
  - `gates`;
  - `guards`: each guard is `{name, expression, inverse}`.

  The cube-reuse certificate uses the `values` and the guards.

## Diagonal certificate (`diagonal-scaling-certificate-v2`)

- `sourceIrSha256` and `newIrSha256` name the pre-diagonal IR and the
  balanced IR. `polynomialSha256` names the omitted `balanced/polynomial.json`.
- `direction` is `old_x_i = 2^twoPower[i] * 3^threePower[i] * new_x_i`.
  `threePowers` and `twoPowers` map every coordinate id, as a string, to an
  integer, which may be negative.
- `rows` has one entry per residual, in the same order, of the form
  `{id, divisorNumerator, divisorDenominator}`. The pre-diagonal row with
  the substitution applied, at the fixed `S`, equals
  `(divisorNumerator/divisorDenominator)` times the balanced row.

## Transport certificate (`transport-certificate.json`)

- `sourceSha256` names the pre-transport IR and `candidateSha256` the
  pre-diagonal IR.
- `blocks` lists one block for each of `detector0`, `detector1`,
  `detector2` and `scalar`. Each block has:
  - `s` and `newV` (the old `h` slot, which now stores `v`);
  - `newQ`, `newQSquare` and `removedSquare` (the old `s2` slot);
  - `semanticOldH`, the affine `H` in old coordinates;
  - `positiveConicInput`, the conic coefficient `b`;
  - `reverseLift`, which maps each private slot id to its polynomial in the
    new coordinates;
  - `privateConsumerRows`;
  - `normalizedNewRows`, the four rows as they appear in the new IR.

Every polynomial uses the IR term format.

## Coordinate map (`compiled/coordinate-map.json`)

- `mapping`: a list of `{sourceId, compactId, name}` for the compiled
  coordinates that are kept. `sourceId` is the IR id.
- `omittedFreeCoordinates`: the ids of the compiled coordinates that occur
  in no residual. They are extended by 0.

## Exact-rewrite certificates (`rewrites/`)

- `stack-public-evidence-ideal-certificate-v1` (#18). Polynomials are lists
  of `[rational string, [coordinate names]]`, and `"$S"` stands for the
  formal parameter. Each entry of `directions` gives:
  - a `map` from target-system coordinate names to base-system polynomials;
  - `identities`, each of the form `{row, combination:[[baseRow, multiplier], ...]}`.

  For every target row, the image under `map` must equal
  `sum(multiplier * baseRow)`. A target row that is not listed must map to
  the base row of the same name. `expectedDelta` lists the row and
  coordinate differences, and `r`, `L` and `displayedConstants` record the
  constants of PROOF.md.
- `stack-public-evidence-cube-reuse-v1` (#13). `afterIdentities` and
  `beforeIdentities` list `{row, lhs, rhs}`. Here `lhs` and `rhs` are sums
  of `[coefficient, [value names]]`, which are products of the IR's named
  affine values. The coefficients `c2`, `c3` and `c4` come from
  `contactRoots`. Each row must be a nonzero multiple of `lhs - rhs`.
  `cubicAliases` names the `t`, `Fsquare`, `Fmiddle` and `deltaCubed` values.

## `INDEX.json`

- `tables[]` gives, for each table:
  - `label`, `pr`, `head`, `packet` and `expectedKey`;
  - `buildDirectory`;
  - `publishedSummary`, copied from the packet's EXPECTED file at `75e76303`;
  - `roles`, which maps each role to a packet path;
  - `omittedPolynomialJson`.
- `files{}` gives, for each copied file:
  - `sha256` and `bytes`, after decompression;
  - `storedSha256` and `storedBytes`, as stored;
  - `origins`: build-relative source paths;
  - the bindings: `pathBinding` (the published hash for that build path),
    `publishedIn` (`commit:file` entries containing the hash) and
    `statedIn` (bound packet files containing the hash);
  - `bound`, and `unboundReason` where `bound` is false.
- `derived{}` describes the files generated here: the rows text and the
  rewrite certificates.
- `omittedFromEveryTable` lists the omitted file kinds and why they were
  left out. `excluded` lists any file whose published hash differed. It is
  empty.
